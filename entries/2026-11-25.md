# 2026-11-25

## [Veille] Drupal Core : RCE via l'installeur exploitée, ajoutée au KEV (CVE-2026-132165)
Une faille critique de l'installeur de Drupal Core, corrigée le 18 novembre, permet à un attaquant non authentifié de prendre le contrôle d'un site existant ou d'exécuter du code côté serveur ; l'équipe sécurité Drupal signale une exploitation sur des sites en production dès le 19 novembre (19:00 UTC).
La CISA l'a ajoutée au catalogue KEV le 24 novembre (avec Idunno.AntiCsrf et Optimizely Web Experimentation), avec une échéance fédérale très courte au 27 novembre : l'exploitation est rapide et opportuniste.
À retenir : mettre à jour vers Drupal 10.6.22, 11.3.22 ou 11.4.13 (selon la branche) ; restreindre l'écriture sur le fichier settings ne bloque qu'une partie des attaques, seul le correctif protège.
Source : https://cybersecuritynews.com/drupal-idunno-anticsrf-optimizely-flaws-exploited/

## [Note] Détection : surveiller les fichiers sensibles et les exécutions avec auditd
auditd est le sous-système d'audit du noyau Linux : les règles sont évaluées en espace noyau et les événements écrits dans /var/log/audit/audit.log.
Deux types de règles utiles : les « watches » sur fichiers (`-w chemin -p rwxa`) et les règles sur appels système (`-a always,exit -F arch=b64 -S execve ...`).
Le champ `-k` pose une clé qui permet de retrouver les événements avec `ausearch -k <clé>` et d'en faire des rapports avec `aureport`.
Le champ `auid` (audit UID) conserve l'utilisateur de connexion d'origine même après un `sudo` ou `su` : c'est lui qui permet d'attribuer une action à une personne.
Exemple, dans /etc/audit/rules.d/ :
`-w /etc/sudoers -p wa -k sudoers_change`
`-a always,exit -F arch=b64 -S execve -F euid=0 -F auid>=1000 -F auid!=unset -k root_exec`
Puis `augenrules --load` et `ausearch -k root_exec -i` pour lire les événements décodés.
Attention au volume : tracer tous les `execve` est coûteux ; on filtre (euid=0, auid humain) et on envoie les logs vers un SIEM, car un root local peut les effacer.
