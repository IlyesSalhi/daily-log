# 2026-11-24

## [Veille] LiteLLM : RCE via l'endpoint de test des guardrails, ajoutée au KEV (CVE-2026-40217)
- Quoi : la CISA a ajouté le 18/11/2026 au catalogue KEV une faille du proxy LLM BerriAI LiteLLM permettant une exécution de code à distance via l'URI `/guardrails/test_custom_code` (réécriture de bytecode). Échéance fédérale : 2 décembre 2026.
- Pourquoi c'est important : d'après GTIG (cité par la presse), des attaquants ont transformé de simples clés d'inférence limitées en identifiants d'administration complets puis se sont installés durablement. Une passerelle LLM concentre les clés API de tous les fournisseurs de modèles.
- À retenir côté défense : mettre LiteLLM à jour, ne pas exposer l'interface d'administration ni les routes de test sur Internet, et faire tourner toutes les clés fournisseurs stockées sur une instance exposée.
- Source : https://letsdatascience.com/news/cisa-adds-four-exploited-flaws-including-litellm-to-kev-cata-4eb52bab

## [Note] SSH : les certificats OpenSSH plutôt que des authorized_keys partout
- Avec `authorized_keys`, chaque serveur doit connaître chaque clé publique : la révocation et le départ d'un employé deviennent un inventaire manuel.
- OpenSSH sait gérer ses propres certificats (pas du X.509) : une CA signe la clé publique de l'utilisateur avec une identité, des principals autorisés et une durée de validité.
- Signer une clé utilisateur valable 8 h pour le principal `ilyes` :
  `ssh-keygen -s ca_user -I ilyes@poste -n ilyes -V +8h id_ed25519.pub` (produit `id_ed25519-cert.pub`).
- Côté serveur, une seule ligne dans `sshd_config` : `TrustedUserCAKeys /etc/ssh/ca_user.pub` (et éventuellement `AuthorizedPrincipalsFile` pour mapper principals et comptes).
- Inspecter un certificat : `ssh-keygen -L -f id_ed25519-cert.pub` (identité, principals, validité, extensions).
- Des certificats courts (quelques heures) rendent la révocation presque inutile ; sinon `RevokedKeys` accepte une KRL générée par `ssh-keygen -k`.
- Même principe dans l'autre sens : un certificat d'hôte (`ssh-keygen -h`) + `@cert-authority` dans `known_hosts` supprime les alertes TOFU.
